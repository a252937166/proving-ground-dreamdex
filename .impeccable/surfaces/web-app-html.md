# Surface brief: App and Dashboard

Scope: the working screens, App (`/app`, web/app.html) and Dashboard (`/dashboard`, web/dashboard.html). Mode: Operate. Built inside the Margin Rescue world set by the Overview brief; no new identity.

App task: enter a public address, set the BTC and ETH moves (or a preset) and a target buffer, read the account at one block, compare the evaluated reductions, and read a recorded execution (fork end-to-end, fork rehearsal of the live plan, live run 1 when it exists). Read-only; execution happens in the owner's own terminal and is documented, never offered as a button.
Dashboard task: watch live BTC and ETH markets and see the state of every proof: tests, fork scenarios, live reconciliations and the live run.
Important states: loading (an analysis takes 15–25 s), refused input, BLOCKED with reasons, NO_ACTION_NEEDED, NO_FEASIBLE_CANDIDATE, an empty account, a run that is pending, RPC failure.
The world lends four things only: type (Geist with tabular figures, Martian Mono for panel titles and step numbers, Geist Mono for hashes and commands), palette (warm graphite panels, rescue orange for the primary action, the selected tab and the active step; mint, cherry and amber for state), dense 13–14px rows, and one signature move: the margin meter, health equity drawn against the dashed maintenance line, moving from the account now to the scenario and, in a recorded run, back above the line from the fills. On the dashboard the same move is the order book ladder with depth bars that travel and a mark that flashes on each tick. Navigation, tabs, inputs, buttons and tables are standard web controls; the scenario panel sits on the right like an order-entry panel.
